## Architecture and admission

`DeterministicMutation` is a pure bounded byte generator. `CorpusMutation` owns finite admission/execution orchestration, `MutationWorkspace` owns temporary input lifetime, and `MutationCommand` supplies explicit single/batch CLI entry points. Target execution always uses the existing `WorkerSupervisor`; the mutation orchestrator never invokes adapters in-process.

Invocation requires an explicit absolute repository root, the exact algorithm ID and bounded count/index. Single reproduction additionally validates target/configuration against the registry and selects the requested target/seed only from the existing **fully validated corpus snapshot**. No arbitrary source path or caller-supplied seed list is accepted. Unknown algorithm, target, configuration, seed or index fails closed. Initial corpus failure launches zero workers. Batch work exceeding its limit is rejected before staging/launch; no partial prefix is silently selected.

Before **each mutation**, source bytes are reread through `InputFile` using the actual target ceiling and checked against the admitted seed length and SHA-256. The exact verified in-memory bytes feed generation. A later source edit therefore cannot change those generated bytes, and any change present before the next read stops that next mutation. Tests alter the source after the first controlled worker and verify the second is not launched. The accepted snapshot is never refreshed from changed files and the manifest/oracle is never rewritten.

Batch order is validated ordinal manifest order, then ascending mutation indices starting at zero. Every invocation is fail-fast on integrity, workspace, supervisor, timeout or cleanup failure. Expected target rejection is a valid completed mutation outcome and does not stop an otherwise successful bounded batch. This exploratory policy is intentionally separate from replay's corpus-oracle comparison, which remains unchanged.

## Versioned generation contract

Algorithm: **deterministic-v1**. Fixed seed: **1049**. Valid indices: **0 through 6 inclusive**, with the mapping below. No time, random API, GUID, PID, scheduling, environment data or filesystem enumeration order affects generation.

The choice digest is SHA-256 over UTF-8 encoding of these LF-separated fields, with no trailing LF:

`deterministic-v1`, `1049`, target ID, seed ID, configuration version, mutation index, uppercase SHA-256 of source bytes.

Decimal fields use invariant culture. The first four digest bytes, interpreted as an **unsigned little-endian 32-bit integer**, select the position. Byte 4 selects replacement/fill value, byte 5 selects amount **1 + byte % 8**, and byte 6 selects the bit. Nonempty position is `position % sourceLength`; insertion position is `position % (sourceLength + 1)`. Empty position is zero.

| Index / operator | Exact behavior |
|---|---|
| 0 / BitFlip | XOR one selected byte with `1 << (digest[6] % 8)`. Empty source becomes one-byte insertion. |
| 1 / Replace | Replace one selected byte with digest[4]; if already equal, XOR the value with 1 so replacement changes that byte. Empty source becomes one-byte insertion. |
| 2 / Insert | Insert one digest[4] byte at the selected inclusive position. At the target ceiling, use Replace with the same choice digest. |
| 3 / Delete | Remove up to eight bytes from the selected offset, limited by the remaining source length. Empty input stays empty; one byte becomes empty. |
| 4 / Overwrite | Fill up to eight contiguous bytes from the selected offset, limited by the remainder. Empty source becomes one-byte insertion. A fill may already equal existing bytes. |
| 5 / Truncate | Retain the prefix before the selected offset. Nonempty output is strictly shorter; empty input stays empty; one byte becomes empty. |
| 6 / Extend | Append 1-8 copies of digest[4], limited by remaining target capacity. At the ceiling, use Replace with the same choice digest. |

The identity records the indexed operator, including when its documented empty/ceiling fallback applies. Generated arrays are independently owned and never modify source bytes. Output length is computed within the registered ceiling before allocation; no growth loop, pooling, unbounded enumeration or PRNG state is used. Degenerate empty deletion/truncation and unchanged overwrite remain well-defined identities, rather than being silently skipped.

Seven fixed vectors independently calculated from the framing/digest rules lock v1 behavior for target filter-asciihex, seed a-success, configuration 1, source byte 3E:

| Index | Generated hex |
|---:|---|
| 0 | 3C |
| 1 | 6D |
| 2 | E83E |
| 3 | empty |

These are tiny owned test vectors, not emitted input logging or newly persisted corpus files. Golden-vector and repeated-generation tests avoid relying only on comparison of the implementation against itself.

## Temporary-file ownership and cleanup

Temporary input uses only the fixed operator-controlled **&lt;repository-root&gt;/artifacts/fuzz/mutation-work** directory, already covered by the existing artifacts/fuzz ignore rule. `git check-ignore` confirmed this path is ignored. No file is written beneath the persisted tests/FuzzCorpus directory. Paths contain no document-derived names; the slot names are fixed **active.lock** and **case.bin**.

Directory components are checked for ordinary directories and observed reparse/device attributes before/after creation. A **CreateNew / FileShare.None** lease admits only one cooperating invocation; a live competing invocation fails without launching. Existing files are not truncated, overwritten or deleted as stale data. After acquiring the lease, foreign directory contents reject admission. Enumeration checks only for the first unexpected entry; this is not recursive discovery.

Each case uses CreateNew, writes only its bounded generated bytes, closes the writer, then holds a **FileAccess.Read / FileShare.Read** handle through worker consumption. The staged file is independently read through InputFile and compared byte-for-byte to generated bytes before launch. This reduces ordinary Windows write/delete races while another process opens the case for reading.

After supervisor completion/cleanup, the read handle closes and the owned case is deleted. Foreign contents detected after a case fail cleanup and stop further launches. Final disposal releases/deletes the owned lease and removes the staging directory if this invocation created it and it is empty. Existing empty operator directories and general artifacts/fuzz parents may remain; successful runs leave no mutation payload, lease or successful-run artifacts. Deletion is **never recursive**. Unknown files are preserved and surfaced as CleanupFailed, not erased to make cleanup pass. Cleanup also runs after rejection, cancellation, timeout, abnormal/protocol failure and source-identity failure. Controlled tests verify each path and explicitly preserve a foreign-file obstacle.

Cleanup failure overrides successful/cancelled execution in the exit status, while counts and any supervisor status remain visible. A real cleanup failure requires operator investigation of this fixed directory; the tooling does not print paths or silently delete evidence. Controlled orphan/foreign-file fixtures are independently cleaned by their owning tests.

## Outcome, identity and output contracts

Only **Completed / TargetResult / worker exit 0 or 1** counts as a completed mutation: 0 is target success; 1 is expected target rejection. Completed worker input failure (exit 2), spontaneous cancellation, unexpected target exception, abnormal exit, malformed protocol, start/capture/termination failure and timeout never count as target rejection. Existing target exception allowlists and worker protocol checks were not changed.

Stable reproduction identity comprises target, seed, configuration, **source SHA-256**, algorithm/fixed seed, index and indexed operator. Every completed attempt has an immutable identity/outcome entry in the library's bounded ordered ledger. A failing attempted case is identified in the summary. Successful single reproduction includes its identity and success/rejection counts. A successful batch summary omits the ledger; its identities can be reconstructed from the admitted manifest and explicit per-seed command count. Generation does not require retained mutation bytes.

JSON schema 1 fields are `schemaVersion`, `algorithm`, `fixedSeed`, `status`, `exitCode`, `failure`, `admitted`, `attempted`, `completed`, `successes`, `rejections`, `failures`, `cancelled`, `identity`, `corpusFailure`, `supervisionStatus`. When present, identity fields are `Target`, `Seed`, `ConfigurationVersion`, `SourceSha256`, `Index`, `Operator`. All text is fixed/closed metadata or validated bounded identity. No bytes, arbitrary child output, raw exceptions, absolute paths, environment contents, PID, timestamp or timing information is emitted.

Attempted counts supervisor requests, including start failure; completed counts only valid success/rejection outcomes. Successes plus rejections equals completed. Failures is a fail-fast invocation indicator, zero for Completed/Cancelled and one otherwise; it does not relabel target rejections as defects. Cancelled indicates the final cancellation outcome; a cleanup failure takes precedence. Supervisor status retains distinctions such as TerminationFailed and Cancelled when available.

| Mutation exit | Status | Meaning |
|---:|---|---|
| 0 | Completed | All requested finite mutations returned valid success/rejection outcomes. |
| 1 | InvalidRequest | Usage, algorithm/index, target/config/seed selection or aggregate budget failed. |
| 2 | IntegrityFailure | Initial corpus validation or per-mutation source identity/read failed. |
| 3 | SupervisionFailure | Abnormal/invalid protocol, worker failure, input failure, start/capture/request failure. |
| 4 | TimedOut | Supervisor case deadline; not target rejection. |
| 5 | Cancelled | Explicit cancellation, with no failed cleanup reported. |
| 6 | CleanupFailed | Temporary cleanup or supervisor termination/reaping failure. |
| 7 | TemporaryInputFailure | Staging/lease/read/write admission failed before worker execution. |

## Security and platform limitations

Execution remains **Windows-local-file-only**; other platforms fail closed through the existing corpus validator. There is no Linux/macOS mutation-execution claim. Pure byte-generation determinism is covered by fixed SHA-256 framing and test vectors; worker/platform readiness is a separate matter.

BCL reparse checks are conservative snapshots, not an atomic filesystem sandbox. They do not prove protection against concurrent parent substitution or distinguish hard links. Holding the case read handle reduces ordinary write/delete races, but the worker still reopens a pathname and physical identity across parent substitution is not proven. A privileged or same-trust actor can undermine operator-controlled directory assumptions. No native API or dependency was introduced to claim stronger containment.

The existing supervisor uses a fresh child, bounded capture/strict protocol, 10-second deadline, independent 5-second cleanup, process-tree termination attempt and root reaping. Root exit does not prove every inaccessible or detached descendant exited. The tests independently reap their controlled orphan. The managed **256 MiB GC heap configuration** is not a hard total-memory/RSS cap: native allocations, stacks and mappings remain outside it. Mini-dump suppression is not a guarantee against all OS crash-report mechanisms. OS file/process calls are not hard real-time guarantees. No exception allowlist, security limit, cleanup contract or release gate was relaxed.
